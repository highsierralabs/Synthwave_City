# Synthwave City: architecture

Synthwave City is a static website: an endless, garish, 80s-synthwave megacity you fly through in the
browser. Neon towers, rivers of flying traffic, shimmering shafts of light, floating holographic
billboards and busy streets, under a striped sun that never sets. Everything is generated by code at
start-up. There are no image, model, font or sound files.

It is a different take on [Afterglow City](https://github.com/J-o-h-n-M/afterglow-city) (MIT), the demo
that prompted it: the same idea of a procedural city you fly through, built on a different stack, with a
different world model and a different look. No code is taken from it (§13, D-01).

This file is the design. How to work on the project is in [Agents.md](Agents.md). `§n` means section n
of this file. Numbers given here are starting values; T13 may retune numbers, never structure (§12).

**Evidence tags**, used here and in Agents.md: `[O]` observed on this machine, `[MV]` observed in the
sibling project Midnight Vector on this machine with the same pinned versions and carried over,
`[W]` from a web source, `[I]` inferred and not tested, `[M]` from memory.

## 1. Overview

### 1.1 What the viewer gets

- A city with no edge. Fly in any direction for as long as you like and the skyline keeps coming.
- **Neon towers:** window grids, glowing edge trim, light bands, animated facade signs, lit crowns,
  spires with blinking lights, and a few megatowers that dwarf the rest.
- **Flying vehicles:** thousands of craft in stacked sky lanes between the towers, with engine glow and
  light trails, plus a handful of large hero ships.
- **Shimmering shafts of light:** sweeping searchlights, beacon pillars that rise out of sight, laser
  fans from tower crowns, and sun shafts through the skyline.
- **Floating holographic billboards:** translucent ad panels hanging in the air with scanlines, flicker
  and glitch, and large rotating wireframe holograms over the plazas.
- **Busy streets:** dense ground traffic with headlights and tail lights, crowds on the sidewalks,
  street lamps, wet asphalt that mirrors the neon.
- **A synthwave sky:** gradient dusk, stars, a striped sun on the horizon, a wireframe mountain range.
- **A soundtrack** synthesized live: bass arpeggio, pads, gated drums, a lead line. The neon pulses on
  the beat.
- Two ways to look: an automatic cinematic tour, and free flight with collision against buildings.

### 1.2 Requirements

| Id | Requirement |
|---|---|
| R1 | Static site. `npm run build` gives a `dist/` folder that works from any path on any static host. |
| R2 | No asset files. Geometry, textures, text and audio are all generated at run time. |
| R3 | Deterministic. The same seed gives the same city on every machine. |
| R4 | Endless. No world edge, no loading pauses, no precision decay however far or long you fly. |
| R5 | 60 fps at 2560x1440 on the reference desktop GPU (RTX 4070 SUPER) at the `high` tier; a `low` tier that runs on integrated graphics. |
| R6 | WebGL2 only. A clear message, not a blank page, when WebGL2 is missing or the context is lost. |
| R7 | Works with keyboard and mouse, and with touch. Starts muted until a gesture; audio is optional. |

### 1.3 Non-goals

Gameplay, scoring, multiplayer, a day-night cycle, building interiors, physically based lighting,
WebGPU, and mobile performance tuning beyond the `low` tier.

## 2. Tech stack

Language: **TypeScript 6** (strict), shaders in **GLSL ES 3.00**. Runs in the browser; Node 24 for tooling.

| Piece | Choice | Version | Why |
|---|---|---|---|
| Renderer | **three.js**, `WebGLRenderer` on WebGL2 | 0.187.0 | Mature instancing, cameras and render targets; runs in every current browser, including Firefox, Safari and phones |
| Shading | custom GLSL in `ShaderMaterial` | n/a | Every surface is procedural and emissive; three's lit materials are not used |
| Post-processing | **postprocessing** (pmndrs) | 6.39.6 | Merged effect passes; mip-chain bloom, tone mapping, chromatic aberration, vignette |
| Audio | **Web Audio API** | browser | Synthesized music and ambience, no samples |
| Text and ad art | **Canvas 2D** drawn into a texture atlas at start-up | browser | Billboard content without image files |
| Build and dev server | **Vite** | 8.3.5 | Fast dev server, static build |
| Unit tests | **Vitest** | 5.1.0 | Pure logic: city plan, lanes, wrap maths, collision, tour |
| Browser checks | **Playwright** (library, not the test runner) | 1.64.1 | Screenshots and a smoke run in real Chromium on the GPU |
| Lint | **ESLint** + typescript-eslint | 10.14.0 / 8.72.1 | Style and module boundaries |

Runtime dependencies are exactly two: `three` and `postprocessing`. Versions are pinned exactly and are
the set already proven together on this machine [MV].

Rejected: raw WebGPU as in the demo (narrower browser reach, and nothing here needs compute);
three's `WebGPURenderer` with TSL (API still moving; less proven); a game engine (far more than a
fly-through needs); glTF or texture assets (R2).

```
    holograms/   floating billboards and wire holograms                      T09

```

### 3.2 Dependency rules

- `contracts` imports nothing from the project, and three only as types.
- `core` and `city` are pure: no three, no DOM, no `Math.random`, no `Date.now`.
- A layer imports `contracts`, `core` and three. **A layer never imports another layer, `post`, `audio`,
  `camera` or `app`.** Layers do not know each other exist; they share only the plan and the shared
  uniforms.
- `engine` imports `contracts` and `core`, and finds layers and the pipeline through a lazy glob
  (§3.4), never by name.
- `app` is the only module that may import everything.

ESLint enforces these with `no-restricted-imports` per folder.

### 3.3 Frame flow

```
requestAnimationFrame(ts)
  clock.advance(ts)                     time, dt, loop phase (§4.3)
  camera driver writes the CameraPose   src/camera, or the harness camera
  engine wraps the pose, updates shared uniforms
  for each layer: layer.update(frame)   CPU work only where needed; no allocation
  pipeline.render(frame)                reflection pass -> scene -> bloom -> grade -> canvas
```

Almost everything that moves is animated in vertex shaders from `uTime` and `uLoop`, so `update`
is empty for most layers and the CPU cost per frame is close to constant.

### 3.4 Layers

A layer is one visual subsystem behind one interface (`src/contracts/layer.ts`):

```ts
interface Layer {
  readonly id: LayerId;
  init(ctx: LayerContext): void | Promise<void>;   // build everything, add to ctx.scene
  update(frame: FrameState): void;                 // per frame, allocation-free
  dispose(): void;
}
```

Each layer lives in `src/layers/<id>/index.ts` and exports `createLayer()`. The engine discovers layers
with `import.meta.glob('../layers/*/index.ts')`, so adding a layer touches no shared file, and the
harness can mount any subset: `/dev/?layers=sky,buildings`. A layer that fails to load or throws in
`init` is reported and skipped; the rest of the city still renders.

`LayerContext` gives a layer the scene, the renderer, the camera (read-only), the `CityPlan`, the
`SharedUniforms`, the `QualitySettings` and a seed. Quality is fixed for the life of the page: changing
the tier reloads (§9).

### 3.5 The pipeline

`src/post` exports `createPipeline(host)` and returns a `FramePipeline` (`render`, `setSize`,
`dispose`). The engine loads it through the same lazy glob. Without it (or with `?post=0`) the engine
renders the scene straight to the canvas with a plain tone map, which is what a layer sees in the
harness if `post` is broken.

## 4. World model

### 4.1 One tile, wrapped

The city is a single square **tile**, `TILE = 6400` m on a side, that repeats in x and z. Nothing is
streamed or regenerated. Instead every shader places its geometry **relative to the camera, wrapped**:

```glsl
vec2 d = anchor.xz - uCam.xz;            // both in tile coordinates, 0..TILE
d -= SC_TILE * floor(d / SC_TILE + 0.5); // nearest copy: -TILE/2 .. TILE/2
```

The wrap is applied to an object's **anchor** (a building's centre, a vehicle's position), never per
vertex, so objects stay whole. The three.js camera sits at `(0, y, 0)` and only rotates; `modelMatrix`
is identity everywhere. The camera's own x and z are kept wrapped into `0..TILE` on the CPU.

Consequences:

- **R4 holds by construction.** No coordinate on the GPU exceeds a few thousand metres, so float32
  never runs out however far the viewer flies. Nothing loads or unloads.
- The viewer sees at most `TILE/2 = 3200` m in any direction before the same building could appear
  twice. Fog, plus the far fade below, hides that distance.
- three's frustum culling would be wrong, so every mesh sets `frustumCulled = false`.

All placement goes through one shared GLSL function, `sc_place(anchor, local)` (§8.3). No layer writes
its own wrap.

### 4.2 The far fade

Between `R0` and `R1` (2500 m and 3100 m at `high`), `sc_place` scales heights towards zero, so
buildings, vehicles and beams sink into the ground before the wrap distance instead of popping. The
ground itself is one large plane centred under the camera whose shader draws the periodic street
pattern out to the horizon, so the city reads as continuing forever; beyond `R1` it shows only streets
and a sparkle of distant lights in the fog. Lower tiers pull `R0`/`R1` in (§9).

### 4.3 Time

`uTime` is seconds in `[0, LOOP)` and `uLoop = time / LOOP` in `[0, 1)`, with `LOOP = 4096` s. Both are
computed in double precision on the CPU and wrapped there.

- **Motion along a lane is loop-periodic:** `s = fract(laps * uLoop + phase) * TILE` with integer
  `laps`. Speed is therefore quantised to `TILE / LOOP = 1.56` m/s steps, and the wrap at the end of
  the loop is seamless. Worst-case position error is about 2 cm at 100 m/s [I].
- Cosmetic flicker and shimmer may use `uTime` directly; a one-frame discontinuity every 68 minutes is
  accepted.
- No shader accumulates time, and no layer keeps its own clock.

### 4.4 The street grid

The tile is `40 x 40` cells of `CELL = 160` m. A road runs along every cell boundary, in both axes.
Every fourth line is an **avenue**.

| | Street | Avenue |
|---|---|---|
| Corridor half-width (centre line to building line) | 12 m | 20 m |
| Carriageway half-width | 8 m | 14 m |
| Lanes per direction | 2, at 2 m and 6 m from centre | 3, at 4, 8 and 12 m; 2 m median half-width |
| Sidewalk | 4 m | 6 m |

Traffic keeps right. Because the grid is this regular, the ground shader, the city plan and the traffic
all derive it from the same handful of constants (`src/contracts/constants.ts`, mirrored in the GLSL
chunk), and nobody needs a road mesh. Road surface is `y = 0`.

Air above every road is always free of buildings, at any height. That one fact makes street traffic,
sky lanes and the camera tour collision-free by construction.

### 4.5 The city plan

`src/city` turns a seed into a `CityPlan` (`src/contracts/city.ts`), pure data that every layer reads:

- **Cells:** per cell a district (`lowrise`, `midtown`, `downtown`, `plaza`, `mega`), a palette bias and
  a height class, also packed into a 40x40 RGBA8 array that the engine uploads as `uCellTex`.
- **Boxes:** every building is one or more axis-aligned boxes (podium, shaft, setbacks, crown), in one
  `Float32Array`, 12 floats per box: centre x, base y, centre z, size x/y/z, style, two palette indices,
  seed, flags, building id.
- **Lanes:** street lanes at `y = 0` and sky lanes at fixed altitudes above the avenues. Lanes running
  along x and along z use different altitudes, so crossing traffic never meets.
- **Sites:** typed anchor points with position, size, yaw, colour and seed: `holoPanel`, `holoObject`,
  `searchlight`, `pillar`, `laser`, `roofLight`, `ticker`. The plan guarantees a site's volume is clear
  of every box.
- **Landmarks:** the megatowers and plazas, for viewpoints and the tour.
- **Queries:** `heightAt(x, z)` and `collide(pos, radius)`, both wrap-aware.

Skyline: a low-frequency height field with a few downtown peaks sets each cell's height class.
Typical heights are 15 to 60 m in `lowrise`, 60 to 200 m in `midtown`, 180 to 480 m in `downtown`, and
600 to 900 m for the roughly dozen megatowers.

Expected sizes at full density [I]: about 1,600 cells, 9,000 buildings, 16,000 boxes, 550 lanes,
600 sites.

## 5. Look

### 5.1 Art direction

Garish on purpose. The darks are deep indigo, never grey or black; everything else is saturated light.
Surfaces carry almost no diffuse light; the picture is made of emission, fog and bloom.

| Index | Name | sRGB | Use |
|---|---|---|---|
| 0 | Hot magenta | `#ff2bd6` | signature trim, curbs |
| 1 | Electric cyan | `#19f0ff` | signature trim, holograms |
| 2 | Ultraviolet | `#9b4dff` | fills, fog accents |
| 3 | Sunset orange | `#ff7a1a` | sun, warm windows |
| 4 | Laser yellow | `#ffe14d` | accents, headlights |
| 5 | Acid green | `#49ff7a` | rare accent |
| 6 | Signal red | `#ff2740` | tail lights, aviation lights |
| 7 | Ice white | `#dff4ff` | cores, stars |

The palette is `PALETTE` in `src/contracts/palette.ts` and `uPalette[8]` in GLSL. Layers pick colours by
index so a mood can re-tint the whole city.

### 5.2 Light levels

The frame is rendered in linear HDR. Bloom keys on luminance, so what glows is decided by how bright a
surface writes, on one shared scale:

| Band | Linear value | What |
|---|---|---|
| L0 | 0.00 to 0.15 | unlit surfaces: asphalt, walls, hulls |
| L1 | 0.4 to 1.0 | lit windows, screens seen far away; reads as lit, barely blooms |
| L2 | 1.5 to 4 | neon trim, signs, holograms, light trails; blooms |
| L3 | 4 to 10 | small hot cores: headlights, beacons, the sun's disc, strobe peaks |

Large areas stay at or under L1; L3 is for small things. A layer that paints a whole facade at L3
whites out the frame.

### 5.3 Fog and distance

Exponential fog, denser near the ground, tinted by direction: warm towards the sun, violet away from
it. The sky's horizon band uses the same function (`sc_fogColor`), so distant geometry dissolves into
the sky rather than ending. Emission is fogged like everything else; L2 and L3 survive it and are what
you see far away.

### 5.4 Per-layer techniques

- **Sky:** a camera-centred dome drawn at the far plane. Vertical gradient, hashed stars with twinkle,
  the sun (disc with scrolling horizontal cut-outs and a halo), a ridge of wireframe mountains, a haze
  band on the horizon.
- **Ground:** one plane. The fragment shader derives streets, lane markings, crossings, glowing curbs,
  plaza grids and block tints from tile coordinates and `uCellTex`, filters every line analytically
  against its pixel footprint, and adds the mirrored city from the reflection pass, roughened by wet
  asphalt. Street lamps are instanced posts with glow sprites.
- **Buildings:** instanced unit boxes; the vertex shader reads the box's size and style from instance
  attributes, the fragment shader builds the facade in metres: window grid with hashed lit pattern,
  edge trim, bands, fins, storefronts at street level, animated sign panels, beat-driven equaliser
  facades, lit crowns. Window detail fades to its average when a window is smaller than a pixel.
- **Street life:** instanced low-poly cars placed along lanes in the vertex shader, with additive light
  quads for headlights, tail lights and the pools they throw on the road; far traffic becomes moving
  dashes; pedestrians are small instanced impostors near the camera.
- **Air traffic:** instanced craft in sky lanes with engine glow, strobes and stretched light trails;
  a few large CPU-animated hero ships.
- **Beams:** quads that turn about their own axis to face the camera, with a soft cross-section,
  falloff along the length and scrolling shimmer noise. Additive.
- **Holograms:** panels textured from a canvas-drawn atlas of invented ads, with scanlines, flicker,
  glitch bands and colour fringing; wireframe solids over plazas; ticker rings round megatowers.

### 5.5 Blending rule

Every translucent effect is **additive**, with depth test on and depth write off. Nothing needs
back-to-front sorting, which the wrapped world could not provide anyway. Draw order is by `renderOrder`
band: opaque 0, sky 50 (drawn at the far plane after the opaques), beams 100, holograms 200,
glow sprites 300.

### 5.6 Frame pipeline

1. **Reflection pass** (`medium` and up): the scene from a camera mirrored in the road plane, into a
   reduced-size target. Objects on three layer 1 (`SC_LAYER_NO_REFLECT`) are skipped. The ground reads
   it through `uReflTex` and `uReflMatrix`.
2. **Scene pass** into a half-float target, multisampled on `high`.
3. **Bloom** (mip chain), then **tone mapping**, a little chromatic aberration, vignette, and an optional
   CRT look (scanlines and grain). The tone curve is chosen to keep neon saturated rather than
   bleaching it to white.
4. Optional **sun shafts**: a radial blur from the sun's screen position, masked by scene depth.

### 5.7 Moods

A `Mood` is a set of numbers (sky colours, sun colours, fog, exposure, star amount, palette tint). Three
ship: `sunset` (default), `midnight` and `miami`. Switching eases all values over a few seconds. Moods
live in `src/contracts/moods.ts`.

## 6. Audio

One `AudioContext`, created on the first gesture. A lookahead scheduler plays a generated synthwave
loop: four-on-the-floor kick, gated snare, hats, a sixteenth-note bass arpeggio, side-chained pad
chords and a sparse lead with delay, plus a bed of city hum. All sound is oscillators, noise buffers
and filters.

The beat drives the picture: the engine exposes `uBeat` (pulse, bar phase, step, energy). When audio is
running it supplies the beat; otherwise the engine derives the same tempo from its clock, so the city
pulses either way.

## 7. Camera and input

- **Tour** (default): a drone that follows the road grid, since road corridors are clear at every
  height: cruising an avenue, banking through an intersection, climbing a megatower, dropping to
  street level. Deterministic from the seed and the clock.
- **Free flight:** mouse look with pointer lock, `W A S D`, `Q`/`E` for down and up, `Shift` to boost.
  The camera is a sphere that slides along building boxes (`plan.collide`).
- **Viewpoints** `1` to `6`, derived from landmarks.
- **Touch:** drag to look, hold to fly, second finger to boost.
- Any input in the tour hands control to the viewer; `Space` returns to the tour.

The camera writes a `CameraPose` (position in tile coordinates, orientation, field of view). It never
touches three objects directly.

## 8. Frozen contracts

`src/contracts/**` is written by T00 and then frozen. Changing it needs a contract change request
(Agents.md). Additive changes are cheap; anything else needs every consumer checked.

### 8.1 Files

| File | Holds |
|---|---|
| `constants.ts` | `TILE`, `CELL`, `CELLS`, road dimensions, `LOOP_SECONDS`, `BPM`, render-order bands, `SC_LAYER_NO_REFLECT` |
| `palette.ts` | `PALETTE` and index names |
| `moods.ts` | `Mood`, `MOODS` |
| `quality.ts` | `QualityTier`, `QualitySettings`, `QUALITY` |
| `city.ts` | `CityPlan`, `Lane`, `Site`, `Landmark`, box layout constants, district and style ids |
| `layer.ts` | `Layer`, `LayerContext`, `FrameState`, `SharedUniforms`, `FramePipeline`, `PipelineHost` |
| `camera.ts` | `CameraPose`, `CameraDriver` |
| `audio.ts` | `BeatSource` |
| `glsl.ts` | `SC_COMMON`, the GLSL chunk every shader prepends |

### 8.2 Shared uniforms

One object per uniform, created by the engine and shared **by reference**: time and loop, beat, wrapped
camera position, far-fade radii, fog and sky colours, sun direction and colours, palette, global glow,
wetness, resolution, the cell texture, and the reflection texture and matrix. Layers spread
`ctx.uniforms` into their materials and add their own.

### 8.3 The GLSL chunk

`SC_COMMON` declares the shared uniforms and provides: hashes and value noise; `sc_place` (wrap plus far
fade) and `sc_project`; `sc_fogColor` and `sc_fog`; `sc_neon(index)`; road-grid helpers that mirror
`constants.ts`; filtered-line helpers; and `sc_axisBillboard` for beams and trails. A unit test keeps
the constants in the chunk equal to the TypeScript ones.

## 10. Robustness

- No WebGL2, or renderer creation throws: a styled message page, no canvas.
- Context lost: pause, show a notice, resume on restore; reload if it does not come back.
- A layer that throws at `init` is skipped and named in the console and the debug overlay.
- Tab hidden: the loop stops, audio suspends, and the clock does not jump on return (`dt` is clamped).
- `localStorage` is always wrapped in try/catch.
- `prefers-reduced-motion`: the tour moves slowly and without banking; strobes are softened.

## 13. Decision log

| Id | Decision | Why |
|---|---|---|
| D-01 | New code on a new stack, not a fork of the demo | The request is a different version; the demo's raw-WebGPU single-file design does not fit a modular, multi-task build, and WebGL2 reaches more browsers |
| D-02 | three.js on WebGL2, not WebGPU | Reach, and a toolchain already proven on this machine |
| D-03 | One wrapped tile instead of streamed chunks | Endless with no streaming code, no precision problem and no per-frame CPU work; the cost is a repeat every 6.4 km, hidden by fog and the far fade |
| D-04 | Heights sink at the far fade | Cheaper and cleaner than dithered fade; no popping at the wrap distance |
| D-05 | Motion in vertex shaders, loop-periodic | Tens of thousands of movers at near-zero CPU; seamless time wrap |
| D-06 | Additive-only translucency | No sorting in a wrapped world |
| D-07 | Layers found by glob, never imported by name | Tasks stay independent; a broken layer cannot break the build of another |
| D-08 | Quality tier fixed per page load | Layers build once; no runtime re-allocation paths to get wrong |
| D-09 | Screenshots judged by eye, no pixel baselines | Procedural, animated, GPU-dependent output; baselines would be noise |
| D-10 | Perpetual sunset, no day-night cycle | The synthwave look is one time of day; moods give variety |

## 14. Open risks

| Risk | Mitigation |
|---|---|
| The reflection pass doubles scene cost | Reduced-size target; off at `low`; ground falls back to a fake glow |
| Window grids shimmer at distance | Analytic filtering to the average; MSAA at `high`; checked with a moving-camera frame sequence |
| The tile repeat is noticed from high altitude | Fog and far fade tuned in T13; megatowers placed so no two copies share a view |
| Bloom washes the frame out | The L0 to L3 bands (§5.2); T13 balances layers against each other |
| Text in the ad atlas depends on system fonts | Generic font stacks; art relies on shapes more than glyphs |
| Only one GPU and one browser are tested here | Stated as untested in the README; nothing claims otherwise |
